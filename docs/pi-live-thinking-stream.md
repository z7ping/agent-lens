# Pi Live 工具间思考的实时关联修复

## 问题与原因

连续工具调用之间，新的思考未在当前输出位置出现，运行结束后的历史快照才补齐。

Pi SDK 1.2 的 `AssistantMessage` 不提供必填 `id`。原先服务从
`message.id` 获取当前回复身份，缺失时增量事件只剩 `contentIndex`。
前端因此将不同回复的第零个思考块关联到同一节点，后续内容更新到旧位置。
持久化快照使用独立会话条目 ID，所以结束后可以恢复完整内容。

## 修复与验证

- 每次 assistant 开始时，保留原生 ID；不存在时生成独立的临时实时身份。
- 开始、增量及结束事件保持同一身份；下一次回复使用新的身份。
- 临时身份仅服务于实时事件关联，不写入 Pi 持久化会话条目。
- 回归用例覆盖没有 ID 的两次回复及中间工具事件，检查思考增量归一化后的身份独立。
- SDK、Adapter 与前端增量投影定向测试通过；发行构建通过。
- 全量测试中 Web 包有 12 项现有契约/性能用例失败；全量类型检查中两个 Web 测试仍引用已不存在的 `LIVE_TASK_ROUND_FACT_LIMIT`。本次未修改这些文件。
- 表现层门禁在命令型 Tool 摘要的字号所有权断言处失败，本次未修改样式。
- 真实 Pi 连续工具调用的浏览器流式验收仍待执行，不能以静态快照代替。
