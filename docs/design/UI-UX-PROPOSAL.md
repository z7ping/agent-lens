# AgentLens 1.0 Web 表现层规范

> 状态：**当前有效**。
>
> 唯一高保真基线：`docs/design/mockups/v2/`
>
> 本文只约束 1.0 Web 的信息层级、交互与视觉表现，不改变 Source / Storage / Surface、Core Contract、Cordis、Daemon 或双发行架构。

## 1. 产品问题

AgentLens Web 必须直接回答：

1. 这次任务发生了什么；
2. 哪些事实有 Evidence（证据）支撑；
3. 哪些工具和能力资产真正被使用；
4. 本机有哪些智能体与资产，哪些只是发现、哪些已经使用；
5. 哪些原始资产已经被安全备份和验证。

发现不等于使用，未观察到不等于不存在，未知不等于 0。

## 2. 一级信息架构

顶部只保留五个一级页面：

- 任务复盘
- 工具分析
- 使用洞察
- 智能体概览
- 资产备份

不增加“使用分析 / 资产中心”等二级产品层。

## 3. 全局 Shell

- Header 使用正式 AgentLens Logo，不使用字符占位。
- 主题切换使用 SVG 图标。
- 后台服务、存储与实时通道合并为一个状态入口；异常时显示真实状态，不硬编码接口没有提供的端口。
- Header、Inspector、抽屉和轮次导航不使用背景模糊毛玻璃。
- 窄窗口优先隐藏品牌文字，Logo 保留；导航允许横向滚动，不截断一级页面入口。
- 正常界面文字不得低于 12px。

## 4. 字号阶梯

| 层级 | 字号 | 用途 |
| --- | ---: | --- |
| 页面标题 | 22px | 页面主标题 |
| 区块标题 | 16px | 主要内容区标题 |
| 正文 | 14px | 对话、说明正文 |
| 列表 / 表格主体 | 13px | 会话、工具、资产主体 |
| 辅助 / Caption | 12px | 时间、路径、徽章、表头、状态说明 |

高信息密度不能通过 8–11.5px 极小字号实现。

## 5. 来源与采集状态

正式支持的内建来源显示为：

- Claude Code
- Codex
- Pi
- Hermes
- OpenCode

来源必须区分：

- 是否支持；
- 是否检测到；
- 是否启用采集。

例如“已检测 · 未启用采集”不能显示成“未安装”。来源色只用于小型点状标记和细描边，状态仍必须有文字。

## 6. 任务复盘

- 会话列表和会话详情独立滚动。
- 会话按“今天 / 昨天 / 更早”分组，并显示相对时间。
- 用户消息右侧，智能体消息左侧。
- 最近轮与错误轮优先展开；长会话使用 turn-rail 做定位。
- round-nav 只承担轮次筛选和当前页动作，不承担定位。
- Evidence（证据）默认可见。
- “显示原始记录”只补充来源原始事件和载荷，不隐藏 Evidence。
- Inspector 使用“详情 / 证据 / 原始数据”三页签。
- Inspector 支持 Esc 关闭、焦点陷阱和焦点返回。
- 工具使用统一 SVG 类型图标，不使用“读 / 改 / ›_”等字符占位。
- 搜索采用防抖；source / project / range / status / q 写入 URL。

## 7. 工具分析

- 顶部四项：最高频、失败最多、平均最慢、可靠归因覆盖。
- 表格固定为：工具 / 调用 / 会话 / 成功率 / 失败 / 平均耗时。
- 表头支持鼠标和 Enter / Space 排序。
- 点击工具打开详情抽屉；抽屉支持 Esc 关闭。
- 详情展示真实 Top 3 相关会话并可直接进入任务复盘。
- 当前接口没有逐次错误载荷时，不使用演示错误文本冒充事实。
- 来源展示产品名称，不直接泄漏 `claude-code` 等内部 sourceId。

## 8. 使用洞察

- 只基于已经采集到的会话、工具和资产事实。
- 展示统计覆盖、会话 / 轮次 / 工具 / 明确失败、趋势、周期变化、智能体使用结构、能力资产采用和重复工作流模式。
- 样本超安全上限时明确标注抽样，并关闭可能失真的周期比较。
- 不展示无产品价值的 productId 等内部技术标识。
- 产品文案优先使用“智能体 / 技能 / MCP（模型上下文协议）”。

## 9. 智能体概览

- 左侧来源列表，右侧单一智能体详情；不并排铺多张大卡。
- 状态区分“已检测”和“采集中”。
- 可观测能力展示状态、采集方式和不完整原因。
- “最近真正用过”只统计有证据的技能和 MCP 调用，并使用真实比例条。
- 技能生命周期使用真实比例；未报告状态显示“—”，不按 0 计算。
- 高频资产矩阵中的“未观察到”不解释为“一定不存在”。

## 10. 资产备份

- 使用与其它页面相同的五来源名称和来源色。
- 资产类型与正式代码一致：技能、MCP、插件、扩展、钩子、记忆、规则、会话 / 历史、关键配置、其他。
- 显示保护范围、快照、校验、导入、导出和恢复预演。
- 当前 1.0 只开放恢复预演，不直接写回原智能体目录。
- 凭据、令牌、私钥等敏感内容默认排除。
- 恢复预演抽屉支持 Esc 关闭。

## 11. 状态与首次运行

首次运行固定三步：

1. 检测智能体；
2. 启用采集并确认后台服务 / 实时通道状态；
3. 产生一条可复盘会话。

Hook 是具体 Source 的采集实现，不单独作为产品步骤。

加载、空状态、错误、实时断开和后台新数据都必须保留当前内容和用户阅读位置，错误原因不被演示文案覆盖。

## 12. 原型与代码的同步规则

`docs/design/mockups/v2/` 是唯一当前高保真基线。

- 代码实现与原型表现有偏差时，按本规范和真实能力修正；
- 正式能力比静态稿更完整时，反向更新原型；
- 不为了 1:1 伪造数据、端口、错误载荷或未实现能力；
- P1 / P2 控件不得提前进入 1.0 当前稿；
- 历史探索版本只存在于 Git 历史，不再保留并列原型文件。
