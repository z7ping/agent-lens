# AgentLens 1.0 Web 表现层规范

> 状态：**当前有效，原型已进入正式程序适配前冻结检查。**
>
> 唯一高保真基线：`docs/design/mockups/v2/`
>
> 本文只约束 1.0 Web 的信息层级、交互与视觉表现，不改变 Source / Storage / Surface、Core Contract、Cordis、Daemon 或双发行架构。

## 1. 产品目标

AgentLens Web 必须直接回答：

1. 这次任务发生了什么；
2. 哪些事实有证据（Evidence）支撑；
3. 哪些工具和能力资产真正被使用；
4. 本机有哪些智能体与资产，哪些只是发现、哪些已经使用；
5. 哪些原始资产已经被安全备份和验证。

发现不等于使用，未观察到不等于不存在，未知不等于 0。

任务复盘不是聊天界面，也不是日志界面，而是**以对话为主线、以执行轨迹为证据的智能体任务复盘界面**。

## 2. 一级信息架构

顶部只保留五个一级页面：

- 任务复盘
- 工具分析
- 使用洞察
- 智能体概览
- 资产备份

顶部导航已经通过选中态表达当前一级页面，因此正文区域不再重复显示“工具分析 / 使用洞察 / 智能体概览 / 资产备份”等大标题或产品介绍。可以保留语义 `<h1>` 供无障碍使用，但视觉上隐藏。

任务复盘中的会话标题属于当前数据内容，不受此规则影响。

## 3. 全局壳层与背景

- 顶部使用正式 AgentLens Logo，不使用字符占位。
- 主题切换使用 SVG 图标。
- 后台服务、存储与实时通道合并为一个状态入口；异常时显示真实状态，不硬编码接口没有提供的端口。
- 顶部、详情检查器、抽屉和轮次导航不使用背景模糊毛玻璃。
- 窄窗口优先隐藏品牌文字，Logo 保留；导航不得截断一级页面入口。
- “全部智能体 +”菜单必须处于非裁切层，不能被工具栏滚动容器或正文覆盖。
- 正常界面文字不得低于 12px。

浅色主题使用冷中性色阶：

- 页面画布：`#F5F7FA`
- 白色数据层：`#FFFFFF`
- 次级区域：`#EEF2F6`
- 分割线：`#E1E6EC`
- 强分割线：`#D5DBE3`

统一的是色彩体系，不是强制所有区域同色：

- 工具分析：属于高密度连续数据页，筛选工具栏以下的主数据阅读区使用连续白色数据层；冷灰只作为应用外层画布，不切断 KPI、表格、异常项与能力资产之间的连续阅读。
- 使用洞察、智能体概览、资产备份：冷灰画布承托白色卡片、表格和工具栏。
- 任务复盘：外层冷灰，左侧会话区浅灰，右侧阅读区白色。

## 4. 字号阶梯

| 层级 | 字号 | 用途 |
| --- | ---: | --- |
| 会话 / 辅助规范页标题 | 22px | 当前会话标题、设计系统等非一级业务页标题 |
| 区块标题 | 16px | 主要内容区标题 |
| 正文 | 14px | 对话、说明正文 |
| 列表 / 表格主体 | 13px | 会话、工具、资产主体 |
| 辅助说明 | 12px | 时间、路径、徽章、表头、状态说明 |

一级业务页面名称已经由顶部导航表达时，不再为了使用 22px 标题而额外占用首屏。

高信息密度不能通过 8–11.5px 极小字号实现。

## 5. 来源与采集状态

正式支持的内建来源显示为：

- Claude Code
- Codex
- Pi
- Hermes
- OpenCode

来源必须区分是否支持、是否检测到、是否启用采集。例如“已检测 · 未启用采集”不能显示成“未安装”。来源色只用于小型点状标记和细描边，状态仍必须有文字。

存在智能体筛选的一级页面统一使用“全部智能体”；快捷入口通过 `+` 管理，弹层不得被工具栏裁切。

## 6. 任务复盘

### 6.1 布局与长会话

- 左侧会话列表约 320px，右侧为主要阅读区；原型阅读内容最大宽度约 1320px。
- 会话列表和会话详情独立滚动。
- 会话按“今天 / 昨天 / 更早”分组，并显示相对时间。
- 左侧继续存在更多会话时，鼠标滚轮或滚动条滚动到底部自动加载下一批，每批最多 40 条；底部必须有明确提示，而不是伪装成需要点击的按钮。
- 最近轮、错误轮与当前关注轮优先展开；长会话保留轮次轨用于定位。
- 轮次筛选只承担“全部 / 有错误 / 耗时较高”和当前页操作，不替代轮次轨定位。
- 加载更早轮次、向后增量加载、失败重试、新记录提示和跟随最新状态必须保留正式实现能力。

### 6.2 执行轨迹表达

- 用户消息在右侧，使用高对比度深色气泡。
- 智能体消息在左侧，使用中性表达，不用成功绿色冒充普通回复状态。
- 轮次使用横向分隔和紧凑摘要，不恢复大面积轮次卡片。
- 生命周期使用单排轨迹：图标 + 中文事件 + 简短说明，右侧保留证据、来源与时间。
- 可观察过程片段使用弱强调色块，强度低于错误和警告；只展示真实可观察片段，不臆造思考内容。
- 工具执行使用紧凑可折叠分组，保留次数、状态、耗时、错误和工具类型；正式产品使用 SVG 类型图标。
- 后台活动与普通交互轮次语义区分，不强行编号成用户轮次。

### 6.3 证据与详情

- 证据（Evidence）默认可见，不能为了视觉降噪隐藏。
- 用户、智能体与可观察过程片段都保留真实证据入口。
- 长消息保留“展开全文 / 收起到 5 行”。
- Markdown 内容保留“查看源码 / 返回渲染”。
- “显示原始记录”只补充来源原始事件和载荷，不隐藏证据。
- 详情检查器使用“详情 / 证据 · N / 原始数据”三页签。
- 工具详情保留命令、路径、查询、目标、结构化输入、输出 / 错误、证据与原始数据。
- 生命周期、权限、上下文压缩 / 摘要、子智能体、模型变化、产物更新等语义事件保留可检查能力。
- Pi 关系存在时保留会话树。
- 详情检查器支持 Esc 关闭、焦点陷阱和焦点返回。

## 7. 工具分析

- 进入页面直接看到关键数据，不再重复显示页名和介绍段落。
- 筛选工具栏以下的主数据区使用连续白色数据层，KPI、工具表格、需要关注与可归因能力资产保持同一阅读背景，不在中途切换成冷灰画布。
- 顶部四项：最高频、失败最多、平均最慢、可靠归因覆盖。
- 表格固定为：工具 / 调用 / 会话 / 成功率 / 失败 / 平均耗时。
- 工具图标保持紧凑，主体尺寸不应挤占表格信息。
- 表头支持鼠标和 Enter / Space 排序。
- 点击工具打开详情抽屉；详情展示真实相关会话并可进入任务复盘。
- 当前接口没有逐次错误载荷时，不使用演示错误文本冒充事实。
- 来源展示产品名称，不直接暴露内部来源标识。

## 8. 使用洞察

- 进入页面直接展示统计范围和数据，不再重复“长期观察 / 使用洞察 / 介绍段落”。
- 只基于已经采集到的会话、工具和资产事实。
- 核心指标为：会话 / 交互 / 工具调用 / 明确失败。
- 展示趋势、周期变化、智能体使用结构、能力资产采用和重复工作流模式。
- 样本超过安全上限时明确标注抽样，并关闭可能失真的周期比较。
- 不展示无产品价值的内部技术标识。

## 9. 智能体概览

- 左侧来源列表，右侧单一智能体详情；不并排铺多张大卡。
- 状态区分“已检测”和“采集中”。
- 可观测能力展示状态、采集方式和不完整原因。
- “最近真正用过”只统计有证据的技能和模型上下文协议（MCP）调用，并使用真实比例条。
- 技能生命周期使用真实比例；未报告状态显示“—”，不按 0 计算。
- 高频资产矩阵中的“未观察到”不解释为“一定不存在”。
- 顶部快捷智能体和左侧完整来源列表目前职责不同；在下一步程序适配中不得未经确认擅自删除其中一层。

## 10. 资产备份

- 资产备份已经是 1.0 当前能力，不再标记为未来功能。
- 使用与其它页面相同的五来源名称和来源色。
- 资产类型与正式代码一致：技能、模型上下文协议（MCP）、插件、扩展、钩子、记忆、规则、会话 / 历史、关键配置、其他。
- 显示保护范围、快照、校验、导入、导出和恢复预演。
- 当前 1.0 只开放恢复预演，不直接写回原智能体目录。
- 凭据、令牌、私钥等敏感内容默认排除。
- 页面可保留“本地真实数据 / 刷新扫描”等有操作价值的状态，不重复显示页名与长介绍。

## 11. 状态与首次运行

首次运行固定三步：

1. 检测智能体；
2. 启用采集并确认后台服务 / 实时通道状态；
3. 产生一条可复盘会话。

钩子（Hook）是具体来源的采集实现，不单独作为产品步骤。

加载、空状态、错误、实时断开和后台新数据都必须保留当前内容和用户阅读位置，错误原因不被演示文案覆盖。

## 12. 中文与技术术语

- 用户可见界面默认中文优先。
- 必须保留英文缩写时使用“中文（English）”或“中文名称（缩写）”形式，例如“模型上下文协议（MCP）”“证据（Evidence）”。
- 来源产品名、路径、命令、代码、原始事件字段可以保留原文。
- 原始数据检查器允许展示来源真实英文值，但默认阅读层优先中文语义。

## 13. 原型与代码同步规则

`docs/design/mockups/v2/` 是唯一当前高保真基线。

- 当前任务复盘正式原型固定为 `review.html`；不存在并列的 trajectory / history 版本，历史方案通过 Git 历史查看。
- 代码实现与原型表现有偏差时，按本规范和真实能力修正。
- 正式能力比静态稿更完整时，反向更新原型；不能为了 1:1 删除正式能力。
- 不为了 1:1 伪造数据、端口、错误载荷或未实现能力。
- P1 / P2 控件不得提前进入 1.0 当前稿。
- 原型确认后再进入正式程序适配；适配时共享设计令牌必须重新收敛，不能长期保留原型 / 运行时代码两套色板。
- 历史探索版本只存在于 Git 历史，不再保留并列原型文件。
