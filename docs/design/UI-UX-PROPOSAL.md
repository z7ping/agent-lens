## 1. 输入与依据

- 代码：`packages/web/src/**`（App / ReviewPage / ToolsPage / AgentsPage / client model / 全部 CSS）
- 协议：`packages/protocol/src/**`（review / usage / overview / facets / events 等 DTO）
- 文档：`ARCHITECTURE.md`、`docs/PRODUCT-DIRECTION.md`、`docs/1.0/IMPLEMENTATION-STATUS.md`

产品定位对 UI 的三条硬约束：

1. **回答四个问题**：发生了什么 → 谁证明的 → 属于哪个会话/任务 → 用了哪些 Tool 与资产；
2. **证据优先，不把推测包装成事实**：Evidence / 置信度 / 归因必须可见，"发现 ≠ 使用"必须在视觉上分离；
3. **长会话阅读体验**：SSE 增量更新不得破坏滚动位置与展开状态（AGENTS.md §9 已是硬规则）。

## 2. 现状审计

### 2.1 总体评价

当前 1.0 Web 的**信息架构和交互骨架是健康的**：任务、使用、资产三类产品对象边界清晰，Evidence 徽章体系完整，Interaction 分组 + 工具聚合符合阅读节奏，SSE 合批 + `detailHasNewData` 显式刷新机制正确，`VirtualRoundMount` 懒挂载控制了长会话渲染成本。

主要问题集中在四类：

| 类别 | 摘要 |
| --- | --- |
| 可读性 | 大量 7–10px 字号，低于无障碍下限；信息密度过载 |
| 反馈 | 无骨架屏、空状态缺行动指引、搜索无防抖 |

## 3. 设计原则（Proposal-level）

1. **事实分层呈现**：任何数字旁边能回答"这怎么知道的"——沿用现有 Evidence 徽章，升级为统一规范（见 §5.3）。
2. **先给结论，再给过程**：每个视图首屏回答一个判断题（复盘：哪里出了问题？工具：什么在被用/失败？概览：装了什么、用了什么？）。
3. **安静的中性表面 + 语义色仅作状态**：延续 theme.css 的既有取向，不引入装饰性色彩。
4. **密度分级**：默认舒适密度（正文 ≥13px），提供紧凑模式供重度用户；**最低字号 11px**（替换现 7–10px）。
5. **不打断阅读流**：SSE 新数据 = 轻量浮层 pill + 自动跟随（已有逻辑保留），永不整块重绘。

## 4. 信息架构与导航

### 4.1 五个页面扁平直达

```
任务复盘      "这次任务是怎么完成的？哪里出了问题？"
工具分析      "哪些工具在被真正使用？哪里失败、哪里慢？"
使用洞察      "长期使用形成了哪些可追溯趋势与重复模式？"
智能体概览    "我有哪些 Agent 和资产？哪些真的用过？"
资产备份      "哪些原始资产已经安全保存并可验证？"
```

五个页面都是顶部一级直达入口，不再增加“使用分析 / 资产中心”分类层或二级导航。工具分析与使用洞察、智能体概览与资产备份只通过顺序、留白和细分隔线形成弱关联，避免用户为了进入一个页面先判断抽象分类。

### 4.2 导航增强

- **URL 状态化**：筛选写入 query string（`/review?source=codex&range=7d&status=with-errors&q=storage`），刷新/分享不丢上下文。（修 R2）
- **全局命令面板（⌘K / Ctrl+K）**：跨视图跳转会话、工具、Agent；输入即搜（复用 review 的 search API）。P2。
- **键盘**：
  - `j / k` 或 `↑ / ↓` 在会话列表移动并打开；
  - `Esc` 关闭 Inspector（浏览器 details/抽屉已有部分行为）；
  - `[ / ]` 在轮次筛选间循环；
  - `g r` 刷新当前视图。
- **连接状态**：状态 pill hover 显示 tooltip："Daemon 运行中 · 127.0.0.1:56789 · SSE 已连接"；SSE 断开时 header 下显示一条琥珀色细横幅"实时连接断开，正在重连（第 N 次）——数据可能滞后"。静态稿「状态与引导」页有演示。

### 4.3 文档对齐

将 ARCHITECTURE.md §15 的视图名同步为实现命名与扁平直达导航，消除漂移。（修 S4）

## 5. 设计系统规范

### 5.1 字号阶梯（核心修正）

现状 body 14px 但组件层 7–10px 泛滥。提案阶梯（最小 11px）：

| Token | 值 | 用途 |
| --- | --- | --- |
| display | 20px/700 | 页面标题 |
| title | 16px/700 | 会话标题、卡片标题 |
| body | 14px/400 | 正文、气泡内容 |
| body-sm | 13px/400–600 | 列表主文本、表格主体 |
| secondary | 12px/400–650 | 元信息、徽章、表头 |
| caption | 11px | 时间戳、路径、辅助注释（下限） |

映射到代码：AgentsPage 卡片内所有 7–10px 全部提升至 11–13px；表格主体 12–13px；配合密度模式（compact 下各档 −1px，但仍 ≥11px）。

### 5.2 色彩

沿用现有 `--al-*` token 不变（这是当前最大的资产）。两处修正：

- `--al-muted-2` 两套主题下提升对比度至 ≥4.5:1（浅色建议 `#68737F` 级别）；caption 级允许 3:1 但必须 ≥11px；
- 来源色保持三色语义（Codex 绿 / Claude Code 橙 / Pi 紫），新增规则：**来源色只出现在 6px 以下的点状标记与 2px 描边**，不做大面积填充（现状已基本如此，固化为规范）。

### 5.3 Evidence 徽章规范（统一全站）

```
[捕获方式·推导] [置信度]        例：〔运行时捕获〕〔精确〕
- captureMethod 决定图标形状：runtime-hook ●实心 / native-log ○空心 / static-scan ◇虚线框
- derivation 用前缀着色：observed=中性 / derived|estimated|inferred=琥珀描边
- confidence：exact/high=默认，medium=琥珀点，low/unknown=灰
- >2 条折叠为 +N，点击进 Inspector 证据 Tab（唯一展开处）
```

### 5.4 组件清单（静态稿均已演示）

| 组件 | 说明 |
| --- | --- |
| Skeleton | 列表骨架（头像条+双行）、详情骨架（头区+3 个 round 块），shimmer 动画 |
| EmptyState | 图标 + 结论句 + 原因句 + **行动区（可复制命令/按钮）** |
| ErrorBanner | 页级错误条：消息 + 重试按钮；SSE 断开为顶部细横幅变体 |
| LivePill | 右下角浮动"有新记录 ↓N"，替代 round-nav 内联按钮 |
| SortableTable | 表头排序指示 + 单元格内比例条（调用分布/成功率） |
| DrillDrawer | 工具行点击后的右侧抽屉：会话分布、最近错误示例、跳转链接 |
| Funnel | 技能生命周期横向分段条（已安装→可发现→已使用），比例可视化 |
| HeatCell | 跨 Agent 矩阵色块 + 文字双层编码（不只靠颜色） |
| SegmentedNav | round-nav 左侧筛选段 / 右侧动作组分区 |

## 6. 分界面设计方案

> 以下每节对应静态稿的一个标签页，可直接对照查看。

### 6.1 任务复盘（对应静态稿「任务复盘」）

布局保持 `Session List (320px) | Reader` 双栏。

**会话列表**
- 条目改为**轻量卡片**：静止态即有 surface 底 + 1px 描边，与面板底色形成层次，条目边界清晰（hover 加深描边、active 加来源色 3px 内嵌条 + 标题加粗）；
- 按 今天 / 昨天 / 本周 / 更早 分组，组标题 11px caption；
- 条目：第一行 来源点 + Agent 名 + 相对时间（hover 出绝对时间 title）；第二行标题两行截断；第三行 项目 · 调用数 · 错误数（⚠ 前缀红色）；
- 当前选中：左侧 3px 来源色内嵌条（保留现状）。

**讨论项（仅讨论，未实现）：会话列表按项目聚合**

- 可行性：`ReviewSessionSummaryDto` 已含 `projectId/projectName/workspaceId`，`/facets` 已返回项目清单，纯前端分组即可实现，不需要新接口；
- 建议形态：保持时间倒序为默认；面板头提供「按时间 / 按项目」切换。按项目时渲染 sticky 项目组头（项目名 + 会话数），无项目的会话归入「无项目」桶置于末尾；
- 权衡：按项目聚合利于"我在这个仓库里让 Agent 干了什么"的场景，但跨项目的时间线叙事被打断；且项目数量多时组头本身会成为噪音；
- 结论：作为 P1 候选，先在真实数据上验证使用频率再决定是否实现。

**Reader 头部**
- 保持标题+指标结构；指标增加 tooltip 解释口径（如"跨度 = endedAt - startedAt，包含空闲"）。

**Round Nav 重排**（修 R3）
```
┌──────────────────────────────────────────────────────────┐
│ [全部 6] [有错误 2] [耗时较高 2]     最近一轮 │ 跳到最新 ↓ │   ← 筛选段(左) 动作组(右)
└──────────────────────────────────────────────────────────┘
      ↑ "耗时较高"口径移入各按钮 tooltip；说明文字删除
```
- "有新记录 ↓" 从 nav 行移除，改为 Reader 右下角浮动 LivePill（不遮挡内容，永远可见，点击后滚底并 ack——复用现有 `acknowledgeReviewNewData()` 流程）。

**Interaction 流（连续流式呈现 + 左侧结构导轨）**

轮次不再使用独立卡片盒，改为连续流式呈现以消除轮次间的视觉断层；轮次边界用**左侧 3px 竖向导轨段**（类似代码编辑器 fold guide）标记，而非横贯全宽的 1px 细线——长会话快速滚动时，左侧导轨形成稳定的结构节奏，不会被大量工具行淹没：

- 每轮标题退化为「小标签行」（`› 第 2 轮 · 1 错误 · 2分18秒`），元信息右对齐；导轨随轮次内容延伸，收起时只剩标签行高度；
- **轮次导航轨（turn rail，参考 ChatGPT / Codex）**：阅读区最左侧增加一条贯穿的竖轨，每轮对应一组小横线刻度（2–3 条宽度递减，挂在竖轨上）；悬浮刻度在右侧弹出该轮用户消息预览，点击刻度平滑滚动到该轮；当前视口所在轮的刻度高亮（实现层用 IntersectionObserver 跟随），含错误的轮刻度染红——长会话中可先扫左轨定位，再跳转阅读；
- 折叠能力保留（点击标签行收起/展开）；
- 含错误的轮次：导轨段与轮次号染红，远距离扫视可辨（3px 竖条的辨识度显著高于 1px 横线）；
- 工具组降为轻量描边分组（去底色），耗时占比条保留；
- 事件行 / 原始事件折叠组 / 可观察过程片段保持折叠结构；文案不暗示 AgentLens 能读取隐藏思维。

**保留项**（现网已有、重设计中不丢失的能力）：Pi 会话树披露、原始事件折叠组（RawEventGroup）、消息 Markdown「展开全文 / 查看源码」切换、`running` 状态工具行持续可见、会话列表「加载更多」按钮及其进行中态。

**改进点**

- 工具组 summary 增加**迷你耗时条**——按各工具 duration 占比的水平条，慢调用一目了然；
- 含错误轮次的组默认展开（保留），组内错误行加红色左缘条，无需二次寻找（修 R9）；
- 事件行类别色仅保留 warning/subagent 高亮，其余事件统一中性色，减少彩色噪音。

**Inspector 重构**（修 R7）
```
┌─ Inspector ────────────────────────× ─┐
│ apply_patch · 修改 · 失败 · 1.2 秒      │
│ [详情] [证据 2] [原始数据]   ← Tab 化    │
│ ─────────────────────────────────────  │
│ 详情：路径 / 结构化输入 / 错误输出(diff)  │
│ 证据：Evidence 卡片列表（默认定位到此Tab  │
│       当节点来自 inferred/低置信度时)    │
│ 原始：payload JSON                      │
└────────────────────────────────────────┘
```
- edit 类工具输出若为 patch/diff 文本，做轻量 diff 着色（+/− 行染色即可，不引依赖）；
- 证据 Tab 内每张卡带"复制路径"；
- 宽度 min(520px, 94vw) 保留。

### 6.2 工具分析（对应静态稿「工具分析」）

**KPI 行扩为 4 卡**（修 T3/T4）
```
[最高频 bash 128次·23会话] [失败最多 apply_patch 6次] [平均最慢 web_search 4.2秒] [归因覆盖 87% · 未归因42次]
```
- 第 4 卡直接消费 `meta.unattributedToolCalls`，tooltip 解释"普通 Bash/Read 调用不计入资产归因"——把架构里的诚实性变成 UI 语言。

**表格升级**（修 T1/T5）
- 表头可点击排序（默认调用数降序，指示箭头）；

## 7. 关键交互细节

1. **搜索防抖**（修 R1）：`model.setReviewFilters` 对 `search` 字段 250ms debounce（其余筛选立即生效）；请求 generation 机制已有，直接兼容。
2. **相对时间策略**：<1min "刚刚"、<60min "N 分钟前"、当日 "HH:mm"、昨日 "昨天 HH:mm"、更早 "MM/DD HH:mm"；`title` 恒为完整时间。列表/表格用相对，Reader 头部用绝对区间（保留现状 `formatRange`）。
3. **LivePill 行为**：出现条件 = `detailHasNewData && !followingTail`；点击 = 滚底 + ack（完全复用 ReviewPage.tsx:673-686 现有逻辑，只是换位置换皮）；跟随尾部时不出现在线 pill，避免噪音（现状逻辑已正确）。
4. **表格排序**：纯前端内存排序（数据已在客户端），不改 API。
5. **DrillDrawer 跳转**：`navigate(/review/:id)` 后由现有路由参数逻辑接手。
6. **Inspector 打开动画**：120ms translateX，尊重 `prefers-reduced-motion`。
7. **diff 渲染**：仅当 output 为文本且匹配 `^(---|\+\+\+|@@)` 或含成对 +/- 行前缀时启用 +/- 行背景染色；否则走普通 pre。

## 8. 可访问性与性能

- 对比度：muted-2 提升达 WCAG AA（§5.2）；错误/警告色组合维持现有 token；
- 焦点：`:focus-visible` 已有（styles.css:71），新增组件一律带可见焦点环；
- 键盘可操作：排序表头需 `tabindex=0` + `role="button"` + Enter/Space 触发 + `aria-sort`；抽屉 `role="dialog"` + `aria-modal` + Esc 关闭（焦点环管理/焦点陷阱作为 P1 待办）；图标按钮一律带 `aria-label`；
- 色彩不是唯一通道：矩阵热力格、成功率、错误状态均以「色块/色字 + 文字」双层编码；
- 性能：
  - `VirtualRoundMount` 保留；长列表容器加 `content-visibility:auto` 兜底；
  - ToolsPage KPI 计算 `useMemo`（T4）；
  - 会话列表分组为纯展示计算，`useMemo` 包裹；
  - 不引入图表库——漏斗/比例条/热力格全部用 CSS 实现，零依赖。
