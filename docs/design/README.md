## 对齐原则

正式 Web 以 v2.1 当前稿的布局、信息层级、交互密度、字号、间距、断点和状态表达为表现层基线，但不能为了像原型而牺牲事实真实性。

当正式能力比静态稿更完整时，以真实产品语义为准，并同步更新当前原型。例如：

- 智能体必须区分“已检测”和“已启用采集”；
- 可观测能力展示采集方式和不完整原因；
- 工具错误示例如果当前接口没有逐次错误载荷，不使用演示文本冒充真实错误；
- 未报告的生命周期状态保持“未报告 / —”，不能按 0 展示；
- 健康接口没有端口字段时，顶部状态不得硬编码端口；
- Hook 属于具体 Source 的采集实现，不单独作为首次运行产品步骤；
- 未实现的 P1/P2 控件不进入当前 1.0 原型。

## 第三轮 1:1 追平结果

### 全局 Shell

- Header 使用正式 AgentLens Logo；主题切换统一为 17px SVG；
- Header、Inspector、抽屉和 round-nav 不使用背景模糊毛玻璃；
- 正常界面文字下限统一为 12px；表格/列表主体按 13px 层级展示；
- 顶部运行状态统一为“运行正常 / 实时断开 / 运行降级 / 连接中”，悬停使用自定义多行事实提示卡，不硬编码端口；
- 窄窗口只隐藏品牌文字，Logo 和运行状态点保留；
- 导航、状态区和页面工具栏在 1080 / 900 / 820 / 560 等关键断点与正式 Web 使用同一保留策略；
- 五个一级页面共用相同来源名称与来源色；
- Claude Code 不再以 `claude-code` 等内部 sourceId 暴露在用户界面。

### 五来源

内建来源统一为：

- Claude Code
- Codex
- Pi
- Hermes
- OpenCode

正式 Web 与当前原型共用对应浅色/暗色来源 Token。智能体快捷入口统一支持“＋ 管理”，未检测来源也可在管理入口中看见。Hermes / OpenCode 的智能体详情卡也使用自己的来源强调色，不再回退为灰色。

### 任务复盘

- 320px 会话栏、1080px 阅读区和中等窗口堆叠行为与当前稿追平；
- 左右独立滚动、时间分组、相对时间、智能折叠和 turn-rail；
- turn-rail 使用离散刻度，不绘制额外纵向主线；
- 用户消息右侧、智能体消息左侧，不额外显示头像；
- Evidence（证据）默认可见；
- “显示原始记录”使用轻量文字操作，只补充来源原始事件与载荷；
- 可观察过程片段使用左侧细线弱化，原始事件组使用虚线边界；
- Inspector 为紧凑的“详情 / 证据 / 原始数据”分段页签；
- 工具类型统一 SVG；
- 搜索防抖和筛选地址状态化。

### 工具分析

- 四项顶部指标、六列表格、真实比例条、“需要关注”和能力资产归因；
- 表格主体、标题、行距和辅助层级与当前原型追平；
- 五个数值表头支持升序 / 降序，并支持鼠标以及 Enter / Space；
- 工具行支持键盘打开详情；
- 工具详情抽屉支持 Esc 关闭；
- Top 3 真实相关会话可直接进入任务复盘；
- 来源显示产品名称，不显示内部 sourceId。

### 使用洞察

- 当前原型与正式页统一到 1480px 内容宽度；
- 统计覆盖区、28px 指标、230px 趋势区、周期比较和响应式密度追平；
- 卡头、内容分区、重复模式列表与正式组件结构追平；
- 使用“智能体 / 技能 / MCP（模型上下文协议）”产品文案；
- “会话 / 交互 / 工具调用 / 明确失败”等指标名称与正式页一致；
- 不显示无产品价值的 productId。

### 智能体概览

- 左侧 220px 来源列表 + 右侧单智能体详情；
- 来源栏间距、圆角项、资产数量、状态右置和 560px 窄屏横向列表追平；
- “已检测”和“采集中”分开表达；
- 高频资产真实比例条、技能生命周期真实漏斗；
- 可观测能力展示采集方式和原因；
- 高频资产覆盖矩阵扩展到五来源，并在窄窗口使用横向滚动，不压缩状态单元格。

### 资产备份

- 五来源名称和来源色统一；未检测来源在顶部保持不可选状态；
- 当前原型与正式创建器都覆盖 10 类资产：技能、MCP、插件、扩展、钩子、记忆、规则、会话 / 历史、关键配置、其他；
- 创建器按“智能体 / 资产类型”分组，支持数量摘要、“全选 / 清空”和文件引用摘要；
- 创建器保持两列密度，窄屏切单列；
- 敏感信息保护强制开启；
- 恢复预演包含差异摘要、文件列表、底部“仅预览”提示和关闭操作，并支持 Esc；
- 当前 1.0 只做恢复预演，不直接写回任何智能体文件。

### 状态与首次运行

首次运行统一为：

1. 检测智能体；
2. 启用采集并确认运行；
3. 产生一条可复盘会话。

Hook 不再作为独立产品步骤。空态、错误重试、后台服务连接状态和 SSE 断开均继续使用正式 1.0 语义，不用 Demo / Toast 冒充能力。

## 当前验收边界

经过连续“对比 → 修改 → 再对比”后，当前已没有已知的代码 / 静态原型表现差异需要继续留在开发侧。下一步只保留必须依赖真实渲染环境判断的验收：

1. 明暗主题逐页肉眼检查；
2. Windows 常规窗口、窄窗口和高 DPI 下的实际像素、字体抗锯齿与系统缩放；
3. 浏览器 / Electron 原生 `select`、滚动条和焦点环的平台差异；
4. 任务复盘真实长会话滚动、Inspector、原始记录开关和 turn-rail 定位；
5. 工具分析真实数据下排序、抽屉 Esc、相关会话跳转；
6. 五来源检测 / 启用组合状态与来源色；
7. 使用洞察真实数据下的密度、空白日期和长表格；
8. 资产备份真实 10 类资产、敏感排除和恢复预演；
9. 空状态、错误态、首次运行和 SSE 断开恢复。

实机发现像素、字体渲染或平台控件差异时，以本目录当前 v2.1 为唯一对照稿修正，不重新启用任何历史原型。
