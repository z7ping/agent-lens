# AgentLens 长期能力高保真原型说明

更新日期：2026-08-22

> 状态：设计原型，不属于当前 1.0 实现承诺，不改变现有 Contract / Projection / Storage / Runtime。
>
> 对应画板：
> - `docs/design/mockups/backup.html`：资产备份
> - `docs/design/mockups/insights.html`：使用洞察

## 1. 为什么现在补这两个画板

AgentLens 的长期产品定位是“个人 AI 工作环境的观测、资产管理与理解中心”。现有 1.0 Web 已经覆盖“看清”：任务复盘、工具分析、智能体概览。

这两个画板提前把后续两条主线具体化：

- **资产备份**：回答“我的 AI 资产在哪里，怎样可靠地保住、带走、恢复”；
- **使用洞察**：回答“长期真实使用后，我的 AI 工具、资产和工作流形成了什么模式”。

原型用于验证产品形态和信息层级，不代表对应后端能力已经存在。

## 2. 资产备份画板

### 2.1 核心目标

第一阶段首先保证：

> **原样、安全、可验证地保存资产，并能够导出、导入和恢复。**

覆盖对象：

- Skill（技能）；
- MCP（模型上下文协议）配置；
- Rule / Memory（规则 / 记忆）；
- Session / History（会话 / 历史）；
- Plugin / Extension（插件 / 扩展）配置；
- Hook（钩子）配置；
- Agent 关键配置。

### 2.2 原型信息架构

```text
资产备份
├─ 保护范围
│  ├─ 按 Agent 查看资产数量
│  ├─ 当前是否进入最近快照
│  └─ 本地备份目录 / 可用空间
├─ 创建快照
│  ├─ 选择 Agent
│  ├─ 选择资产类型
│  ├─ 敏感信息排除
│  └─ 创建后完整性校验
├─ 最近快照
│  ├─ Manifest（清单）
│  ├─ Hash（哈希）
│  ├─ 文件数量 / 大小
│  ├─ 导出
│  └─ 重新校验
├─ 导入与恢复
│  ├─ 导入备份包
│  ├─ 校验
│  ├─ 差异预览
│  └─ 恢复到原 Agent
└─ 跨 Agent 迁移（后续预演）
   ├─ 语义映射
   ├─ 兼容性判断
   └─ 人工确认
```

### 2.3 明确边界

**备份与迁移不是一回事。**

- 备份追求：原样保存、可校验、可恢复；
- 迁移追求：跨 Agent 语义映射和兼容转换。

第一阶段不应为了迁移而修改原始备份内容。

### 2.4 Session 备份原则

优先保存 Agent 的原始 Session / History 数据。

Canonical Observation（规范观测）、Review Projection（复盘投影）等 AgentLens 自身数据可以作为索引、校验或辅助信息，但不能成为唯一备份内容。

### 2.5 敏感信息原则

默认排除：

- API Key；
- Token；
- Credential；
- 私钥；
- 能明确识别为秘密的字段或文件。

Manifest 可以记录“某项被排除”，但不记录秘密原值。

## 3. 使用洞察画板

### 3.1 核心目标

从现有工具分析的“统计”继续向后演进：

```text
事实 → 统计 → 模式 → 洞察
```

所有洞察必须能够回到 Observation / Evidence 或明确的原始 Session 范围。

### 3.2 原型信息架构

```text
使用洞察
├─ 本期概览
│  ├─ 会话
│  ├─ 工具调用
│  ├─ 真实使用资产
│  └─ 错误会话比例
├─ 使用趋势
│  ├─ 按天 / 周
│  └─ 与上一周期对比
├─ Agent 使用对比
│  ├─ 会话量
│  ├─ 工具调用
│  ├─ 错误会话
│  ├─ 会话跨度
│  └─ 真实使用资产
├─ 常见工作流组合
│  └─ 规范化工具序列统计
├─ 资产采用情况
│  ├─ 高频真实使用
│  └─ 已发现但未观察到使用
├─ 工作方式演进
└─ 洞察证据范围 / 下钻
```

### 3.3 不做综合评分

原型明确不设计：

- Agent 综合分；
- “最佳 Agent”排名；
- 根据会话时间直接判断效率；
- 根据错误率直接判断 Agent 能力；
- 无证据的推荐工作流。

原因：任务难度、项目类型、用户选择等变量会显著影响这些指标。

### 3.4 洞察分层

UI 中区分两类表达：

- **事实**：可以直接从可靠 Observation / Asset Usage / Session 聚合得到；
- **模式**：由足够样本的事实序列统计得到，需要展示样本范围与识别规则。

未来如果引入模型总结，应增加新的 derivation / confidence 表达，不能把模型解释伪装成 observed fact。

---

## 4. 原型数据说明

两个画板中的所有数字、项目名组合、趋势和工作流模式均为**演示数据**，仅用于展示信息层级与交互。

正式实现前需要重新确认：

1. 哪些数据现有协议已经能够提供；
2. 哪些能力需要新的 Projection；
3. 哪些能力需要新的持久化模型；
4. 哪些属于 Source 私有数据，应通过 Source / Adapter 提供；
5. 哪些事实能够可靠归因，哪些只能标记为 unknown / unavailable。

不要根据原型字段反推并强行扩张当前 1.0 Contract。

---

## 5. 与 1.0 的关系

当前 1.0 仍按既定计划收口：

- 真实 Web 使用体验验收；
- Codex / Claude Code / Pi 真实数据核对；
- Windows 安装、启动、托盘、退出、卸载验证；
- 长时间运行与异常恢复；
- 首次启动体验。

资产备份与使用洞察的高保真原型可以作为后续版本输入，但不应打断 1.0 的发布边界确认。
