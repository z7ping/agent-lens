# Codex 原生会话复盘

Codex Source 同时处理 `response_item` 与 `event_msg.item_completed`。两类记录有不同的身份语义，不能只按文本、时间或相邻位置关联。

- 原始记录有 `call_id` 时，调用和结果使用原始关联键。
- `CommandExecution`、`McpToolCall` 等完整操作在同一 TurnItem 内同时提供输入和结果。缺少 `call_id` 时，Source 使用带轮次范围的 `item.id` 派生操作关联键，交给已有共享投影配对。
- 独立 `FunctionCallOutput` 的 `id` 仅标识结果本身，不能当成调用的身份。缺少关联证据时保留独立结果。
- 不可见的 Reasoning 保留原生节点、证据和工具组边界；正文不添加占位思考，也不计入可见思考数。Live 保留正在流式生成的空思考状态。
- 跨页轮次到达 EOF 时，明确的原生轮次结算事件可解除分片状态；没有结算证据时仍保留未完成状态。未读完的尾轮不宣告“最终回复缺失”。
- 普通 Review 数据直接跟随当前轮次 props；只有惰性过程详情使用独立加载缓存，不能用首屏快照遮蔽后续分页。
- 向后分页同时提供共享“继续加载”按钮，避免过程详情默认折叠、正文不足一屏时无法触发滚动加载。

解析器版本为 `24`，以便旧语义派生可以重新解析。原生 Review 仍按需读取原始文件，不需要复制会话正文或手动修改数据库。
