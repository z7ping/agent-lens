# 原生错误样本与 Harness 复盘

错误统计用于发现值得检查的范围；具体错误样本用于判断提示词、工具调用方式、环境检查和重试策略应当如何改进。一次工具失败不等于整个任务失败，样本数量也不等于独立故障数量或任务成功率。

## 使用入口

- 在「洞察 → 使用概览」点击「具体错误」，再点击「查找错误样本」。
- 在「洞察 → 工具分析」打开一个原生工具行，在详情中查找该工具的错误样本；部分观察行也支持这一入口。
- 点击「继续查找」推进后续窗口；点击「停止查找」取消当前读取。
- 展开样本检查原始失败输出、当时可确认的工具输入、所在轮次的用户输入和证据数量。通过「打开原会话」进入完整 Review，再按样本标注的轮次复盘上下文。
- 「复制结构化样本」复制本次样本的 JSON，供本地整理、对比或作为回归案例使用。复制包含原始上下文，请按自己的资料边界处理。

筛选沿用当前智能体、项目和会话活跃时间范围；时间条件选择会话，不表示逐条错误发生时间过滤。工具详情额外按可确认的原生工具名称过滤。没有可靠工具名称的结果不会被猜测归入某个工具。

## 事实与边界

样本来自既有原生目录与 Review 读取接口，经过原有 CapturePolicy 和 Source 授权检查。前端不直接读取宿主文件，不建立新的 SQLite 正文、错误事件表或第二套会话事实链路。

明确失败包含：已配对工具节点的失败状态、跨窗口尚未配对但明确失败的工具结果，以及原生 `turn.error` / `assistant.error` / `turn.failed` 事件。普通文本包含“error”、用户中断或权限拒绝，本身不被这个入口推断为任务错误。

用户输入、工具输入、工具名称、调用 ID 和原始事件 ID 只在原生记录能确认时保留。工具结果与调用不在同一窗口时，输入可能未知；窗口不完整或文本截断时会明确标注。不得根据工具名称、相似文本或相邻时间补造输入、配对关系和根因。

每次用户触发最多推进四个有界请求；优先检查当前目录页中已有失败统计的会话，并在会话间轮转。每次视图最多保留 20 条样本，单字段最多保留 8192 个字符。扫描未结束、源记录变化、部分会话不可读、样本上限和文本截断都不能解释为全量覆盖。已完整校验且明确零错误的会话可以跳过；未知、缺失或部分统计不能当成零错误。

样本仅保存在当前视图内存中；关闭、刷新或改变筛选后不会自动持久化该样本集合，原始记录继续由智能体原生存储持有。需要保留分析集合时主动复制。导出中的覆盖状态、扫描信息、记录 ID 和缺失标记用于避免把部分观察误当完整结果；具体字段类型以实现为准。

## 用于改进 Harness

先用原始错误和上下文形成可复现的失败案例，再分别考虑输入校验、工具选择、权限及环境前置检查、超时预算、重试或降级策略。修改后应使用相同案例复测，结合最终任务结果判断效果。当前功能不自动改写提示词，不推断根因，不自动关联后续重试成功，也不把错误事件比率冒充任务成功率。

实现入口：共享样本读取与展示为 `NativeFailureExamples`，失败判断复用原生窗口统计。来源和读取权限仍由 Daemon、CapturePolicy 与 Source 持有；改进此能力时应继续复用这些边界。
